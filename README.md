# ProxyOverride

适用于支持 JavaScript 覆写的 Mihomo 客户端。导入订阅后，脚本会生成策略组、分流规则、规则集和 DNS 配置。

> **Important**
>
> 脚本会不定期更新。建议偶尔查看仓库的最新版本；更新后在客户端重新导入或刷新脚本，再刷新订阅。

## 开始使用

以 FlClash 为例，在「工具 → 进阶设置 → 脚本」中通过 URL 导入：

```text
https://raw.githubusercontent.com/Elissend/Proxy-override/main/proxy-override.js
```

随后在订阅的「更多 → 覆写」中勾选该脚本，并刷新订阅。其他支持同类覆写脚本的 Mihomo 客户端也可使用，具体入口以客户端说明为准。

## TUN、DNS 与严格路由

TUN 开关由客户端控制，脚本不会启用、关闭或覆盖它。覆写脚本在生成配置时运行，通常无法读取客户端稍后生效的 TUN 状态，因此不能可靠地替代客户端设置。

使用 TUN 时，在客户端开启 TUN、自动路由和 DNS 劫持。个人电脑不需要访问局域网设备时，再开启 `strict-route`。

`strict-route` 的作用是限制流量绕过 TUN。以 Windows 为例，它会限制系统同时通过 WLAN、网线等其他网卡向路由器 DNS 发起查询，从而减少多网卡 DNS 泄露。

代价是局域网连接也可能被限制：路由器管理页、NAS、打印机、局域网游戏、虚拟机或远程工具可能无法正常访问。需要这些功能时，先临时关闭 `strict-route`；确认问题后，再在客户端单独放行所需的局域网网段。

严格路由不会改变本脚本的域名分流规则，只影响流量进入 Mihomo 的路径。不需要局域网访问时，保持启用即可。

脚本使用 Fake-IP 与加密 DNS。国内域名使用阿里 DNS/DNSPod，其他域名使用 Cloudflare 和 Google DoH。Android 的“私人 DNS”、浏览器单独设置的安全 DNS，以及局域网 DNS 可能绕过客户端处理；DNS 测试异常时，应先关闭或统一这些设置。

DNS 泄露测试中，如果显示路由器或运营商的 DNS，一般可以确认存在绕过；若仅显示 Cloudflare、Google 等脚本使用的上游 DNS，需要结合出口 IP 和查询路径判断，不一定属于泄露。

## 策略组与规则

基础策略组为「节点选择」「自动选择」和「故障转移」。业务策略组覆盖 AI、YouTube、Telegram、海外社交、流媒体、Google、开发工具、海外游戏、苹果、微软、国内直连、广告拦截和漏网之鱼。

脚本会清空订阅原有的策略组、规则和规则集，再写入自己的配置；订阅节点会保留。规则顺序为广告拦截、局域网直连、业务分流、国内外规则和兜底规则。

名称包含「剩余、到期、套餐、流量、官网、免费、试用、登录」等关键词的订阅项目会被视为信息节点，不会加入策略组。需要调整时，修改 `isInfoNode` 中的正则表达式。

仓库中的 `proxy-override.yaml` 是独立的 Mihomo 配置模板，适合需要自行管理订阅与配置文件的场景；日常导入订阅时使用 JavaScript 覆写即可。

## 排错

1. 刷新订阅后，确认策略组和规则已替换，并检查「自动选择」中是否出现订阅节点。
2. 某个服务异常时，在客户端的「连接」页面复现一次，记录目标域名、命中规则和策略组。
3. 优先为实际域名添加直连规则，并放在广告和业务规则之前：

   ```js
   R.push('DOMAIN-SUFFIX,example.com,DIRECT')
   ```

4. DNS 查询失败时，先确认节点可用，并检查客户端没有覆盖本脚本的 DNS 设置。

脚本会尝试输出以 `[v3.2]` 开头的信息，但部分客户端不会显示 `console.log`，不能将它作为唯一判断依据。
