# ProxyOverride

适用于支持覆写脚本的 Mihomo 客户端。导入订阅后，脚本会生成策略组、分流规则、规则集和 DNS 配置。

> **Important**
>
> 脚本会不定期更新。建议偶尔检查仓库的最新版本，并在客户端中重新导入或更新脚本后刷新订阅。

## 使用方式

以 FlClash 为例：在「工具 → 进阶设置 → 脚本」中通过 URL 导入：

```text
https://raw.githubusercontent.com/Elissend/Proxy-override/main/proxy-override.js
```

在订阅的「更多 → 覆写」中勾选该脚本，然后刷新订阅。

其他 Mihomo 客户端只要支持同类 JavaScript 覆写脚本，也可以使用；导入入口和脚本接口以客户端说明为准。

## TUN 与 DNS

TUN 是否启用应在客户端中设置，脚本不会替你开启、关闭或覆盖 TUN 参数。这样同一份脚本可用于系统代理和 TUN，也不会把某个平台的路由、权限或应用分流设置带到另一平台。

这是有意保留的边界：覆写脚本一般在生成配置时执行，无法可靠读取客户端随后启用的 TUN 运行状态。以 FlClash 为例，客户端会在脚本执行后写入自己的 TUN 开关、协议栈、DNS 劫持和路由设置，因此脚本无法安全地“自动判断并配置 TUN”。

使用 TUN 时，请在客户端中确认其路由和 DNS 劫持已启用，并在启用后做一次 DNS 泄露测试。Android 的“私人 DNS”、浏览器单独设置的安全 DNS，以及局域网 DNS 都可能绕过客户端的 DNS 处理；如测试异常，先关闭或统一这些额外 DNS 设置再检查。

脚本使用 Fake-IP 与加密 DNS。国内域名使用阿里 DNS/DNSPod，其他域名使用 Cloudflare 和 Google DoH。

## 策略组和规则

基础组包括「节点选择」「自动选择」和「故障转移」。业务组包括 AI、YouTube、Telegram、海外社交、流媒体、Google、开发工具、海外游戏、苹果、微软、国内直连、广告拦截和漏网之鱼。

脚本会清空订阅原有的策略组、规则和规则集，然后写入自己的配置；订阅节点会保留。规则顺序为广告拦截、局域网直连、业务分流、国内外规则和兜底规则。

名称包含「剩余、到期、套餐、流量、官网、免费、试用、登录」等关键词的订阅项目会被视为信息节点，不会加入策略组。需要调整时，修改 `isInfoNode` 中的正则表达式。

仓库中的 `proxy-override.yaml` 是独立的 Mihomo 配置模板，适合需要自行管理订阅和配置文件的场景；日常导入订阅时使用 JavaScript 覆写即可。

## 排错

刷新订阅后，先确认策略组和规则已被替换，并检查「自动选择」中是否出现订阅节点。这比依赖脚本日志更可靠。

脚本会尝试输出以 `[v3.2]` 开头的信息，但部分客户端不会显示脚本的 `console.log`，因此它不能作为唯一判断依据。

某个应用访问国内服务异常时，在客户端的「连接」页面复现一次问题，记录目标域名、命中规则和策略组。优先按域名加直连规则：在 `injectRules` 的前部加入一行，并刷新订阅。

```js
R.push('DOMAIN-SUFFIX,example.com,DIRECT')
```

请将 `example.com` 换成实际域名。把规则放在广告和业务规则之前，避免后面的通用规则先命中。应用名、进程路径和 Android 包名在不同系统中的可用性不同，不放进通用脚本；如果确实需要整应用直连，应在所用客户端的应用分流或进程规则功能中单独设置。

DNS 查询失败时，先确认节点可用，并检查客户端没有覆盖本脚本的 DNS。若仍被检测为 DNS 泄露，确认当前使用的是 TUN 或系统代理中的正确模式，关闭浏览器/系统额外 DNS 后重新测试。
